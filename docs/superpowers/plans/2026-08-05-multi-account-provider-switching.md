# Multi-Account Provider Switching Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let one device hold multiple authenticated accounts per provider (Claude/Codex) and switch which one is active, driven from the web UI.

**Architecture:** Each account is a labeled slot with its own isolated credential folder on the connector (`providers/<provider>/accounts/<accountId>/home`). The database is the single source of truth for which account is *active*; the connector holds no active-state and is a dumb executor told which `accountId` to run under at dispatch time. Switching flips an `active` flag on a `provider_connections` row and applies to the next task.

**Tech Stack:** TypeScript monorepo (pnpm workspaces): Next.js web app, Node connector, Node gateway, Zod contracts (`packages/contracts`), Supabase Postgres migrations (plpgsql), Vitest unit tests, pgTAP SQL tests, Playwright e2e.

## Global Constraints

- Provider enum values are exactly `codex` and `claude` (`ai_provider` in SQL, `ProviderSchema` in contracts). No new provider values.
- Account identity is **not** auto-detected. Every account has a user-supplied `label` (non-empty, ≤ 60 chars). Claude's `subscriptionType` (e.g. `"pro"`) may be captured as a display hint only.
- A newly-added account becomes the active account for its `(device, provider)`.
- Exactly **one** active account per `(device, provider)`, enforced by a partial unique index.
- `accountId` is a UUID generated by the database at setup-request creation and used verbatim as the connector's slot folder name. The connector MUST validate it (`assertSafeAccountId`) before using it in a path.
- Switching accounts never re-runs login; it only flips the DB flag. Switching to an account whose token has since expired fails the task through the existing auth-failure path (no live refresh in this MVP).
- Migrations are additive and backfill existing rows; never drop the `provider_connections` table.
- Node target for connector/gateway is Node 22+ (Supabase client needs a WebSocket global on Node 20 — do not regress).
- Lint real source with `npx eslint src` inside the package (repo-wide `pnpm lint` includes gitignored build noise).

```sql
alter table public.provider_connections
  add column account_id uuid,
  add column label text,
  add column active boolean not null default false;
```

```sql
create or replace function public.create_provider_setup_request(
  target_device_id uuid,
  target_provider public.ai_provider,
  target_label text,
  target_account_id uuid default null
)
returns jsonb
language plpgsql
security definer
set search_path = ''
as $$
declare
  caller_id uuid := auth.uid();
  locked_device public.execution_devices%rowtype;
  current_request public.provider_setup_requests%rowtype;
  resolved_label text := left(nullif(btrim(target_label), ''), 60);
  resolved_account_id uuid := coalesce(target_account_id, gen_random_uuid());
begin
  if caller_id is null or resolved_label is null then
    raise exception 'invalid_provider_setup_request' using errcode = 'P0001';
  end if;

  select device.* into locked_device
  from public.execution_devices as device
  where device.id = target_device_id and device.user_id = caller_id
  for update;

  if locked_device.id is null
    or locked_device.status <> 'active'
    or locked_device.revoked_at is not null then
    raise exception 'invalid_provider_setup_request' using errcode = 'P0001';
  end if;

  select request.* into current_request
  from public.provider_setup_requests as request
  where request.device_id = target_device_id
    and request.provider = target_provider
    and request.status in ('queued','dispatched','installing','authenticating','verifying')
  for update;

  if current_request.id is null then
    insert into public.provider_setup_requests (
      user_id, device_id, provider, account_id, label
    )
    values (caller_id, target_device_id, target_provider, resolved_account_id, resolved_label)
    returning * into current_request;
  end if;

  return jsonb_build_object(
    'id', current_request.id,
    'userId', current_request.user_id,
    'deviceId', current_request.device_id,
    'provider', current_request.provider,
    'accountId', current_request.account_id,
    'label', current_request.label,
    'status', current_request.status,
    'stage', current_request.stage,
    'progressMessage', current_request.progress_message,
    'errorCode', current_request.error_code,
    'errorMessage', current_request.error_message,
    'createdAt', current_request.created_at,
    'updatedAt', current_request.updated_at,
    'completedAt', current_request.completed_at
  );
end;
$$;

grant execute on function public.create_provider_setup_request(uuid, public.ai_provider, text, uuid) to authenticated;
```

> Note: the old 2-arg function still exists after `create or replace` adds the 4-arg overload. Drop it explicitly so callers can't hit the account-less version:

```sql
create or replace function public.upsert_provider_connections(
  target_device_id uuid,
  target_statuses jsonb
)
returns void
language plpgsql
security definer
set search_path = ''
as $$
declare
  target_user_id uuid;
begin
  select device.user_id into target_user_id
  from public.execution_devices as device
  where device.id = target_device_id
    and device.status = 'active' and device.revoked_at is null
  for update;

  if target_user_id is null then
    raise exception 'invalid_provider_connections' using errcode = 'P0001';
  end if;

  -- Update status of EXISTING per-account rows only. label/active are owned by
  -- settle_provider_setup_request and set_active_provider_account respectively.
  update public.provider_connections as conn
  set installation = (item ->> 'installation')::public.provider_installation_status,
      version = item ->> 'version',
      authentication = (item ->> 'authentication')::public.provider_authentication_status,
      compatibility = (item ->> 'compatibility')::public.provider_compatibility_status,
      last_seen_at = now()
  from jsonb_array_elements(target_statuses) as item
  where conn.device_id = target_device_id
    and conn.provider = (item ->> 'provider')::public.ai_provider
    and conn.account_id = (item ->> 'accountId')::uuid;
end;
$$;
```

```sql
create function public.set_active_provider_account(
  target_device_id uuid,
  target_provider public.ai_provider,
  target_account_id uuid
)
returns jsonb
language plpgsql
security definer
set search_path = ''
as $$
declare
  caller_id uuid := auth.uid();
  target_conn public.provider_connections%rowtype;
begin
  if caller_id is null then
    raise exception 'invalid_active_account' using errcode = 'P0001';
  end if;

  select conn.* into target_conn
  from public.provider_connections as conn
  join public.execution_devices as device
    on device.id = conn.device_id and device.user_id = caller_id
  where conn.device_id = target_device_id
    and conn.provider = target_provider
    and conn.account_id = target_account_id
    and device.status = 'active' and device.revoked_at is null
    and conn.installation = 'installed'
    and conn.authentication = 'authenticated'
    and conn.compatibility = 'supported'
  for update;

  if target_conn.id is null then
    raise exception 'invalid_active_account' using errcode = 'P0001';
  end if;

  update public.provider_connections
  set active = (account_id = target_account_id)
  where device_id = target_device_id and provider = target_provider;

  return jsonb_build_object(
    'deviceId', target_device_id,
    'provider', target_provider,
    'accountId', target_account_id,
    'active', true
  );
end;
$$;
```

```sql
create function public.remove_provider_account(
  target_device_id uuid,
  target_provider public.ai_provider,
  target_account_id uuid
)
returns jsonb
language plpgsql
security definer
set search_path = ''
as $$
declare
  caller_id uuid := auth.uid();
  removed public.provider_connections%rowtype;
  promoted uuid;
begin
  if caller_id is null then
    raise exception 'invalid_remove_account' using errcode = 'P0001';
  end if;

  delete from public.provider_connections as conn
  using public.execution_devices as device
  where conn.device_id = target_device_id
    and conn.provider = target_provider
    and conn.account_id = target_account_id
    and device.id = conn.device_id
    and device.user_id = caller_id
  returning conn.* into removed;

  if removed.id is null then
    raise exception 'invalid_remove_account' using errcode = 'P0001';
  end if;

  if removed.active then
    update public.provider_connections
    set active = true
    where id = (
      select id from public.provider_connections
      where device_id = target_device_id and provider = target_provider
      order by last_seen_at desc nulls last
      limit 1
    )
    returning account_id into promoted;
  end if;

  return jsonb_build_object('removed', true, 'promotedAccountId', promoted);
end;
$$;

grant execute on function public.remove_provider_account(uuid, public.ai_provider, uuid) to authenticated;
```

## Out of Scope (this plan)

- **Connector wipes the on-disk credential folder on logout.** `remove_provider_account` hard-deletes the DB row (the account disappears from the UI and can't be dispatched), but the isolated `providers/<provider>/accounts/<id>/home` folder is left on disk. Full cleanup needs a dispatch/ack lifecycle (tombstone → `provider.account.remove` message → connector delete → ack); it is deferred. The credentials remain inside the already-managed isolated home, and account ids are unique so there is no reuse collision.
- Automatic failover on usage limit (option B) — this plan is its foundation.
- Auto-detecting account email/identity.
- Live token refresh when switching to an expired account.
